# 제3자 제공 동의 운영 계약

GoLe의 회원가입은 제3자 제공 동의를 선택 사항으로 둔다. 동의하지 않아도 계정을 만들고
운영팀에 문의하거나 과거 대화를 읽을 수 있다. 다만 거래 상대방 또는 대화 참여자에게 새로
개인정보를 제공하는 아래 기능은 서버가 현재 고지 버전의 동의를 확인한 뒤에만 실행한다.

- 매물 1:1 채팅방과 소셜 1:1·그룹 채팅방 생성
- 그룹 채팅 초대
- 운영팀 문의방을 제외한 새 메시지 전송
- 거래 상대방의 전체 연락처 공개

고지에는 다음 내용을 다른 약관·처리방침 확인과 구분해 표시한다.

- 수신자: 해당 대화 참여자 또는 거래 상대방
- 목적: 대화·거래 협의, 배송 진행 및 분쟁 대응을 위한 연락
- 항목: 대화 기능에서는 계정 ID·메시지·방 제목·참여자 정보, 거래 연락처 공개
  기능에서는 정보주체의 전체 전화번호
- 보유기간: 수신자는 목적 종료 후 지체 없이 삭제한다. 관계 법령 준수 또는 진행 중인 분쟁에
  필요한 경우에만 해당 기간 동안 분리 보관한다.
- 거부 영향: 가입과 운영팀 문의는 가능하지만 위 채팅·연락처 공개 기능은 이용할 수 없다.

## 감사 이벤트

MongoDB의 `third_party_provision_consent_events` 컬렉션은 동의와 철회를 append-only 이벤트로
저장한다. 이벤트에는 계정 ID, 고지 버전, 결정, 동의가 이루어진 기능 경로, 계정별 요청 멱등 키,
서버 시각이 들어간다. 어댑터는 `insert`만 사용하며 기존 이벤트를 수정하거나 지우는 API는 없다.

동일 계정과 `requestId`의 재전송은 원래 이벤트를 반환한다. 같은 `requestId`를 다른 결정이나
버전에 재사용하면 실패한다. 현재 상태는 현재 고지 버전의 가장 최근 이벤트로 판정한다. 버전을
올릴 때 과거 계정을 동의 상태로 백필하지 않는다.

```text
GOLE_THIRD_PARTY_PROVISION_VERSION=2026-09-04
```

문구·수신자·목적·항목·보유기간 중 하나라도 바뀌면 개인정보처리방침과 화면을 먼저 갱신하고 이
버전도 함께 올린다.

## 철회와 최소 공개

철회는 과거 증빙을 덮어쓰지 않고 `WITHDRAWN` 이벤트를 추가한다. 철회 뒤에는 새 방·새 참여·새
메시지·상대방 연락처 공개를 차단하지만, 권리 행사와 분쟁 확인을 위해 기존 대화 읽기는 유지한다.
운영팀 문의방은 동의·철회와 무관하게 사용할 수 있다.

결제창 프리필은 `GET /api/v1/orders/{orderId}/contacts/me`에서 요청자 자신의 번호만 읽는다.
`GET /api/v1/orders/{orderId}/contacts`는 현재 동의를 확인한 거래 당사자에게 상대방 번호 하나만
반환한다. 관리자 예외 처리 API와 혼동하지 않는다.
