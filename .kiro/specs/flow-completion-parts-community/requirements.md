# 부품 요청·커뮤니티 흐름 완성 요구사항

## 확인한 기준

- 부품 요청은 `wanted-parts/spec.md`의 생성·마감·삭제·1:1 대화 API를 그대로 사용한다.
- 커뮤니티 작성은 사진 5장을 받지만 상세는 첫 장만 렌더한다.
- `CommunityDtos`의 작성·수정 본문 상한은 5,000자이고 댓글 상한은 1,000자다. 현재 수정 폼은 2,000자다.
- 댓글 폼은 저장 중에도 입력이 가능하며 성공 응답이 오면 현재 입력 전체를 지운다.

## 요구사항

- R1. 게시글 상세에서 등록한 모든 사진을 원래 순서대로 확인할 수 있어야 한다.
- R2. 작성·수정은 동일하게 공백뿐인 본문을 거부하고 5,000자까지 입력·저장할 수 있어야 한다.
- R3. 댓글 저장 중 중복 제출과 입력 변경을 막고, 실패하면 입력을 보존해 다시 등록할 수 있어야 한다.
- R4. 저장한 댓글은 응답으로 받은 내용으로 즉시 표시하며, 후속 조회 실패 때문에 저장 여부를 오해하지 않게 해야 한다.
- R5. 실제 격리 API에서 세트 상세 → 부품 요청 생성 → 마감·삭제, 커뮤니티 생성 → 수정 → 댓글 등록·삭제를 확인한다.
- R6. 부품 요청 CI의 작성 폼 대기는 세트 번호·로그인·라우트 전환을 분리해 진단하고 근거 없이 timeout을 늘리지 않는다.

## 제외

결제·외부 계정·운영 데이터 쓰기, 부품 카탈로그·새 제안 도메인, 공통 UI·API 계약 확장은 포함하지 않는다.
실제 로컬 API와 합성 응답 회귀 테스트는 검증 결과에서 구분한다.
