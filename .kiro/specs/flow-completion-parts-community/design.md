# 부품 요청·커뮤니티 흐름 설계

## 커뮤니티

- `views/community-post`가 기존 Card 스타일로 전체 사진 목록을 렌더한다. 각 사진의 순서를 접근성 이름에 포함한다.
- 작성·수정 폼은 기존 서버 계약(본문 5,000자)에 맞춰 입력 제한과 공백 검증을 제공한다.
- `features/comment-post`는 동기 제출 잠금과 입력 비활성화로 느린 응답 중 중복 등록·초안 유실을 방지한다.
- 댓글 생성 응답을 상세의 댓글 목록에 추가한다. 조회 재시도는 유지하되 생성 성공을 추가 조회 성공에 의존시키지 않는다.
- 기존 저장 키를 그대로 수정 API에 보내 사진이 유지되는지 회귀 테스트로 확인한다.

## 부품 요청

세트 상세 링크의 주소, 작성 페이지 진입, 복원된 세션, 세트 번호 값 순서로 확인한다. 실제 API 검증은
감독자가 준비한 격리 서버와 시드 세션만 사용하고 테스트가 만든 요청·글은 종료 시 삭제한다.
도움 채팅은 최초 제3자 제공 동의 모달 또는 이미 동의한 회원의 입력창을 기다린다. 모달이
나오면 선택·동의를 실제 제출한 뒤 초안을 검증한다. 기존 로컬 동의 기록이나 실행 순서에 기대지 않는다.
요청자도 채팅 제공 동의가 필요하므로 열린 내 요청에는 계정 보안의 동의 설정으로 가는 링크를
제공한다. 요청 작성 자체에 선택 동의를 강제하지 않고, 동의 설정 후 뒤로 가기로 요청에 복귀한다.
실제 왕복 검사는 요청자가 이 링크로 동의하고 도움 주는 회원이 JIT 동의하는 순서를 포함한다.

## 검증

- 합성 응답: 사진 2장 이상, 2,000자를 넘는 본문 수정, 댓글 느린 응답·실패·재시도·중복 제출을 검증한다.
- 실제 API: 생성·수정·댓글 및 부품 요청 생명주기를 검증하고 응답 상태와 재조회 결과를 확인한다.
- 담당 TypeScript 파일의 Prettier·ESLint 및 전체 웹 타입 검사를 실행한다. 전체 저장소 게이트는 감독자가 통합 상태에서 실행한다.
