# 운영 문의 안내 이행과 누락 관리

## 목적과 근거

사용자가 2026-10-25 기능·디자인을 넘어 기획·운영 누락을 찾아 개발하도록 요청했다. 기준선은 dev `7979e234`다. `launch-stage/spec.md` R21이 미구현이고 다음 공백을 코드에서 확인했다.

- `SupportTicket`은 접수 후 72/240시간 목표만 계산한다. 실제 진행·결과 안내 종류, 메시지, 시각은 저장하지 않는다.
- `SupportChatService.reply`는 답변과 감사를 함께 저장하지만 안내 목적은 구분하지 않는다.
- `AdminSupportView`는 해결 시각을 목표와 비교한다. 해결 처리는 고객 안내의 증거가 아니다.
- 인박스는 최신 최대100건이다. 오래된 미안내 건을 전체 저장소에서 선별·집계하는 기능이 없다.

## 요구사항

- R1. 담당자는 답변을 일반 답변·진행 경과 안내·결과/처리방안 안내로 구분한다. 일반 답변과 내부 메모는 안내 이행으로 세지 않는다.
- R2. 안내 기록은 실제로 저장된 고객 답변의 종류·메시지 ID·발신 관리자 ID·서버 시각을 보존한다. 클라이언트 시각·별도 수동 체크로 완료시키지 않는다.
- R3. 메시지·티켓 상태·안내 기록과 성공한 감사 쓰기는 한 트랜잭션으로 저장한다. 실패 시 부분 기록과 SSE 발행을 남기지 않는다. 감사 쓰기 자체의 실패를 흡수하는 기존 admin-console R8.5는 유지한다.
- R4. 최초 진행 또는 결과 안내가 진행 목표의 근거이며, 최초 결과 안내가 결과 목표의 근거다. 반복 답변·이관·해결·재개는 과거 이행 시각과 최초 접수 목표를 바꾸지 않는다.
- R5. 구버전 티켓의 안내 기록을 추정하지 않는다. 해결했더라도 기록이 없으면 미기록 상태로 표시한다. 실제 읽음·법정 기한 준수를 증명한다고 표시하지 않는다.
- R6. 서버는 보존 중인 전체 문의에서 안내별 미도래·임박·초과·목표 내 안내·목표 후 안내 수와 집계 시각을 반환한다. 현재 목록의 한도와 독립적인 수치다.
- R7. 임박/초과 필터는 저장소 전체에 먼저 적용한 뒤 한도를 걸고 오래된 문의부터 보여준다. 상태·유형 필터와 조합할 수 있고 해결한 미기록 문의도 제외하지 않는다.
- R8. 운영 화면은 임박/초과 요약에서 해당 큐로 이동하고, 선택한 문의의 실제 안내 이력을 확인하며 답변할 수 있다. 기존 배정 전 본문 비공개와 담당자 권한을 유지한다.
- R9. 조회/집계 실패는 빈 목록·0건으로 숨기지 않는다. 답변 전송 실패는 내용과 선택 종류를 보존하고 명확한 재시도를 제공한다.
- R10. 안내 기록은 문의 티켓의 보존·원자적 파기에 포함한다. 본문을 복제하지 않으며 기존 탈퇴·보존 중지·감사 가명화 경계를 보존한다.
- R11. 공통 Tailwind UI와 SUITE/SUIT·흰 바탕·코발트 행동을 유지한다. 320/375/414/768px에서 문구·필터·버튼이 넘치지 않고 키보드로 조작 가능하다.

## 범위와 외부 조건

안내 목표 72/240시간은 기존 내부 운영 기준을 그대로 사용한다. 법률/공휴일 정책을 새로 정하지 않는다. 화면 내 임박/초과 경고와 집계를 제공하며 외부 Discord·SMS·고객 알림 발송은 추가하거나 테스트하지 않는다. 조회 가능한 보존 문의의 현황이며 삭제된 과거 문의까지 포함한 법적 준수 리포트가 아니다.

운영 main 배포, 판매자 신원확인·PG/지급 계약·실송장·스토어/실기기 조건과 결제·공개 잠금은 별도다. 공유 체크아웃과 사용자 WEB3000/API8090 및 다른 작업의 `.codex/`를 유지한다.

## 기획·디자인 합의 보강 (2026-10-25)

- R12. 미해결 문의의 임박/초과 작업 큐와 해결·안내 미기록 확인 큐를 분리한다. 과거 해결 문의50건 이상이 현재 처리할 문의를 가리지 않아야 한다. 과거 고객 재안내를 필수로 요구하거나 안내를 추정해서 채우지 않는다.
- R13. 모바일에서 명시적으로 목록으로 돌아오면 자동 갱신 후에도 목록을 유지한다. 필터가 바뀐 동안 이전 목록을 새 조건의 결과처럼 표시하지 않는다. 로딩·조회 실패·확인된 빈 결과를 분리한다.
- R14. 문의·목록·필터 이동 중 작성한 답변 종류·본문·메모를 현재 화면 메모리에 보관한다. 담당자 권한 상실과 계정 변경에는 민감한 초안을 즉시 폐기한다.
- R15. 동시 담당자 인수와 안내 답변의 트랜잭션 충돌을 실제 Mongo로 확인한다. 응답 유실 뒤 재시도 중복의 현재 보장 범위는 검증 기록과 운영 지침에 명시한다.

`launch-stage` R21 전체는 미완료로 유지한다. 이번 원장·화면 큐/집계와 별도로, 화면 밖 운영 알림과 과거 기간을 재현하는 준수 리포트는 정책·보존·수신 담당과 완료 기준을 정할 후속 작업이다.
