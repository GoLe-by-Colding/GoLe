# 관심태그 테마 매물 알림톡 — 요구사항

## 개요

온보딩에서 선택한 관심태그 14종을 처음으로 활용한다. 판매자가 관심 테마를 지정한 새 매물을
등록하면, 해당 태그를 선택한 적격 사용자에게 카카오 알림톡을 비동기로 발송한다.

## 요구사항

### R1. 매물 관심 테마

- **R1.1** 매물은 `InterestTagCatalog`와 key/label이 같은 14종 중 하나를 선택적으로 가진다.
- **R1.2** 판매자는 매물 등록 시 관심 테마를 선택하거나 `선택 안 함`을 고를 수 있다.
- **R1.3** 알 수 없는 태그 키는 `INVALID_INTEREST_TAG`로 거부한다.
- **R1.4** 기존 매물처럼 저장 필드가 없거나 읽을 수 없는 저장값은 `null`로 흡수한다.

### R2. 수신 자격과 개인정보

- **R2.1** 전화 인증 완료, 마케팅 동의, 활성 계정 조건을 모두 만족한 사용자만 후보가 된다.
- **R2.2** 판매자 본인은 수신자에서 제외한다.
- **R2.3** 계정별 일일 발송 상한을 적용한다.
- **R2.4** 발송 직전에 자격과 매물 활성 상태를 다시 확인한다.
- **R2.5** 아웃박스에는 전화번호를 저장하지 않고 수신 계정 ID만 저장한다.
- **R2.6** 전화번호 원문, 템플릿 변수, 매물 제목을 경고 로그에 기록하지 않는다.

### R3. 2단계 아웃박스

- **R3.1** 매물 등록 트랜잭션에는 `FANOUT` 잡 한 건만 결정적 ID로 적재한다.
- **R3.2** 워커는 `_id` 커서 기반 페이지 조회로 적격 수신자를 찾고 `DELIVERY` 잡을 적재한다.
- **R3.3** `DELIVERY` ID는 `listingId:recipientAccountId`, `FANOUT` ID는
  `fanout:listingId`로 고정해 재처리 중복을 방지한다.
- **R3.4** 한 lease에서 처리할 페이지 수와 매물당 최대 수신자 수를 제한한다.
- **R3.5** 팬아웃 계속 처리는 실패 시도 횟수를 증가시키지 않는다.
- **R3.6** 매물 등록은 알림 연계 실패로 롤백되지 않는다.

### R4. 워커 복구와 실패 분류

- **R4.1** 워커는 lease 기반 원자 점유, 지수 백오프, 최대 시도 횟수와 `DEAD_LETTER`를 제공한다.
- **R4.2** 동의 철회, 계정 비활성, 매물 비활성은 실패가 아닌 `SKIPPED`로 종료한다.
- **R4.3** `RATE_LIMITED`, `PROVIDER_FAILURE`만 재시도한다.
- **R4.4** `INVALID_REQUEST`, `AUTHENTICATION`, `PROVIDER_REJECTED`는 즉시
  `DEAD_LETTER`로 종료한다.
- **R4.5** 접수 여부가 불명확한 `ACCEPTANCE_UNKNOWN`은 중복 발송을 막기 위해 재시도하지 않고
  즉시 `DEAD_LETTER`로 종료한다.
- **R4.6** 종료 상태 문서에만 보존 기한을 설정한다.

### R5. 설정과 운영 안전

- **R5.1** 기능은 기본 비활성이며 하나의 `enabled` 설정이 적재와 워커를 함께 제어한다.
- **R5.2** 활성화 시 템플릿 ID가 비어 있으면 모든 환경에서 기동을 실패시킨다.
- **R5.3** staging/production/prod에서 활성화했는데 CoolSMS가 비활성이면 기동을 실패시킨다.
- **R5.4** 일일 상한이 1 미만이면 기동을 실패시킨다.
- **R5.5** 테마 라벨, 40자로 줄인 매물 제목, 매물 링크를 설정된 변수명으로 전달한다.

## 비범위

- 새 `NotificationType` 또는 인앱 알림.
- 매물 검색·필터·정렬 변경.
- 모바일 매물 등록 UI.
- 관리자 재시도 API.
- 판매자당 일일 팬아웃 상한.
- 카카오 템플릿 생성·승인과 실제 운영 발송.
