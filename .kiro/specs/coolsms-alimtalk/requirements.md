# CoolSMS 알림톡 발송 — 요구사항

## 개요

GoLe 백엔드가 승인된 카카오 알림톡 템플릿을 CoolSMS(SOLAPI)를 통해 발송할 수 있도록
독립적인 출력 포트와 어댑터를 제공한다. 기존 인앱 알림 저장 흐름과 계정 모델은 변경하지 않는다.

## 요구사항

### R1. 단건 알림톡 발송
- **R1.1** 호출자는 국내 휴대폰 번호, 승인된 템플릿 ID, 템플릿 변수 맵을 전달한다.
- **R1.2** 수신번호의 공백과 하이픈은 제거하고 `010`으로 시작하는 11자리 번호만 허용한다.
- **R1.3** 카카오 채널 연동 ID(`pfId`)는 환경설정으로 관리한다.
- **R1.4** 알림톡 실패 시 SMS/LMS 대체 발송은 사용하지 않는다.

### R2. 접수 결과와 실패
- **R2.1** CoolSMS의 정상 접수(`2000`)를 성공으로 판단하고 `groupId`, `messageId`, 상태를 반환한다.
- **R2.2** 정상 HTTP 응답이어도 등록 실패 목록, 빈 응답, 식별자 누락, 예상 밖 상태가 있으면 실패한다.
- **R2.3** SDK 예외는 애플리케이션 포트의 실패 유형으로 변환하고 SDK 타입을 외부에 노출하지 않는다.
- **R2.4** 네트워크·빈 응답처럼 실제 접수 여부가 불명확한 실패는 별도로 구분한다.
- **R2.5** 중복 발송을 피하기 위해 자동 재시도하지 않는다.

### R3. 설정과 보안
- **R3.1** 연동은 기본 비활성이며 `coolsms.enabled=true`일 때만 어댑터를 등록한다.
- **R3.2** 활성화 시 API 키, API 시크릿, 카카오 채널 ID가 모두 필요하며 누락 시 시작을 실패시킨다.
- **R3.3** 비밀값, 템플릿 변수, 전체 전화번호를 로그에 남기지 않는다.

### R4. 동시성
- **R4.1** 어댑터는 요청별 메시지 객체를 생성해 공유 가변 상태를 두지 않는다.
- **R4.2** 단건 동기 발송만 제공하며 CoolSMS의 계정 단위 rate limit 초과는 호출자에게 실패로 반환한다.

## 비범위

- 기존 `NotifyUseCase`와의 자동 연결 및 사용자 전화번호 저장/조회.
- 배치, 예약 발송, 큐/outbox, 자동 재시도.
- 최종 단말 수신 결과 웹훅과 발송 이력 저장.
- SMS/LMS 대체 발송과 발신번호 설정.
- 알림톡 템플릿 생성·조회·승인 상태 관리.
