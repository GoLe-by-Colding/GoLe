# 커뮤니티 피드 참여·확장 (community-engagement)

## 목적

커뮤니티는 초기 시드 몇 건을 보여주는 진열장이 아니라 사용자가 계속 탐색하고 반응하는 제품이어야 한다.
새 글이 들어오는 동안 다음 페이지를 읽어도 같은 글이 중복되거나 기존 글을 건너뛰지 않아야 하고,
로그인 사용자의 반응은 새로고침과 페이지 추가 로딩 뒤에도 일관돼야 한다.

## 결정

### D1. 공개 배열 API는 호환용으로 유지하고 페이지 API를 추가한다

기존 `GET /api/v1/community/posts`는 홈·사이트맵 등 기존 소비자를 위해 유지한다. 커뮤니티 화면은
`GET /api/v1/community/posts/page`를 사용하며 `items`와 `nextCursor`를 받는다.

### D2. offset 대신 createdAt + id 키셋 커서를 사용한다

정렬은 `createdAt DESC, _id DESC`로 고정한다. 다음 요청은 마지막 행보다 오래된 시각 또는 같은 시각의
더 작은 ID만 조회한다. 첫 페이지 이후 새 글이 위에 추가돼도 offset 이동으로 인한 중복·누락이 생기지
않는다. `beforeCreatedAt`과 `beforeId`는 둘을 함께 보내거나 모두 생략해야 한다.

### D3. 초기 6개 뒤에는 사용자가 명시적으로 더 불러온다

초기 화면은 카드 6개로 빠르게 그린다. `게시글 더 보기`는 다음 6개를 기존 목록에 중복 제거 후 붙이고,
마지막 페이지에서는 사라진다. 실패 시 기존 글을 보존하고 같은 버튼에서 재시도할 수 있다. 필터·검색은
현재까지 불러온 글을 대상으로 한다는 사실을 결과 문구에 표시한다.

### D4. 서버 컴포넌트는 인증 쿠키 하나만 API에 전달한다

Next 서버의 초기 피드 요청에는 `gole_session`만 전달한다. 전체 브라우저 Cookie 헤더를 복사하지 않는다.
이로써 초기 HTML의 `likedByViewer`가 실제 세션과 일치하고 분석 쿠키는 API로 새지 않는다.

### D5. 검색과 주제 조건은 페이지를 자르기 전에 서버에서 적용한다

검색창과 주제 탭은 현재 브라우저에 들어온 카드만 거르지 않는다. `GET /posts/page`에 `q`와 `topic`을
보내고 Mongo 쿼리가 공개 상태·주제·본문 또는 작성자 조건을 먼저 적용한 뒤 같은 키셋 커서로 자른다.
검색 문자열은 정규식 문법으로 해석하지 않고 리터럴로 escape하며 100자로 제한한다. 빠른 연속 입력은
250ms 디바운스하고 이전 요청을 취소한다. 인기순은 전역 랭킹 정책이 생기기 전까지 **현재 검색 결과**
안에서만 정렬한다고 화면에 명시한다.

### D6. 첫 팔로우 전에는 최근 공개 활동으로 콜드스타트를 메운다

팔로잉 피드가 비어 있다는 이유로 빈 화면만 보여주면 새 사용자는 누구를 팔로우할지 판단할 근거가
없다. 팔로우한 매물 또는 글이 없는 축에 한해 최근 활성 매물 6개와 공개 글 6개를 추천으로 채운다.
추천을 팔로잉 결과처럼 속이지 않고 `처음 만나볼 새 매물`·`지금 둘러볼 이야기`로 구분하며,
팔로우 소식이 생기면 같은 자리에서 자동으로 팔로잉 결과를 우선한다. 추천 API 한쪽이 실패해도 다른
축과 실제 팔로잉 결과는 유지한다.

## 요구사항

- [x] R1. 첫 페이지는 최대 6개와 다음 커서를 반환한다.
- [x] R2. 같은 `createdAt`을 가진 글도 ID 보조 정렬로 중복 없이 이어진다.
- [x] R3. 마지막 페이지는 `nextCursor: null`이며 더 보기 버튼이 사라진다.
- [x] R4. 커서 시각과 ID 중 하나만 전달하면 `COMMUNITY_CURSOR_INVALID` 400을 반환한다.
- [x] R5. 추가 요청 실패는 기존 목록을 지우지 않고 인라인 오류와 재시도를 제공한다.
- [x] R6. 로그인 사용자의 첫 페이지에는 본인의 좋아요 여부가 포함된다.
- [x] R7. 주제·검색 조건은 전체 공개 게시글에 적용된 뒤 페이지네이션된다.
- [x] R8. 잘못된 주제는 자유 글로 강등하지 않고 400으로 거부한다.
- [x] R9. 검색어 정규식 메타문자는 리터럴로 처리하고 100자를 넘는 검색어는 거부한다.
- [x] R10. 입력 중 이전 검색 요청은 취소하며 실패 시 현재 조건 그대로 재시도할 수 있다.
- [x] R11. 첫 팔로우 전에도 최근 매물·공개 글과 작성자/판매자 진입점을 보여주며 추천임을 명시한다.

## 실제 런타임 검증

2026-09-03 로컬 런타임(`web :3010`, `api :8090`)의 실제 게시글 8건으로 확인했다.

1. 초기 피드는 정확히 6건과 `게시글 더 보기`를 표시했다.
2. 더 보기를 실행하자 중복 없이 8건으로 늘었다.
3. 마지막 페이지의 `nextCursor`가 소진돼 더 보기 버튼이 사라졌다.
4. 실제 좋아요를 등록한 뒤 새로고침해 선택 상태와 1건이 복원됐고, 취소·재새로고침 후 0건을 확인했다.
5. 첫 6건에 없던 `드디어 에펠탑 완성! 3일 걸렸네요` 글을 `3일`로 검색해 전체 데이터에서 1건이
   반환되는 것을 확인했다. 미상 주제 요청은 `COMMUNITY_TOPIC_INVALID` 400으로 거부됐다.

## 후속

- 인기순은 전체 기간 단순 좋아요 수가 아니라 시간 감쇠·신고 제외를 포함한 랭킹 정책을 별도 정의한다.
- 피드 노출·상세 진입·반응 이벤트를 개인정보 최소화 원칙 아래 집계해 북극성 지표를 만든다.
