# 설계

## 컨셉과 톤

**수집가의 브릭 선반**: 흰 선반 위의 상품이 주인공이고 도구는 조용하고 정확하다. 즐거움은 기존 고래와 작은 브릭 포인트에서 나온다. 장식용 그라데이션·새 캐릭터·과장된 수치는 추가하지 않는다.

| 역할 | 기준 |
| --- | --- |
| 주 행동·선택·초점 | brand-600, #1D4ED8 |
| 작은 놀이 포인트 | accent-500, #EAB308 |
| 표면·구분 | 흰색, neutral-50 #FAFAFA, neutral-200 |
| 본문·보조 정보 | neutral-900 #18181B, neutral-600 #52525B |
| 오류·주의 | 기존 danger·warning 토큰 + 구체적인 문장 |
| 제목 / 본문 | 로컬 SUITE 700 / SUIT 400·600·700 |

값의 정본은 `apps/web/src/app/globals.css`이며 이 문서는 용도를 정의한다. 안내는 해요체, 버튼은 행동명(검색·필터 초기화·다시 불러오기), 거래 상태는 짧은 명사(예약 중·판매 완료)로 쓴다. 기본 버튼과 입력은 44px, 모서리는 기존 토큰으로 통일한다. 초점은 즉시 보이는 2px 외곽선이다. 흰 입력에는 brand-600, 밝고 어두운 배경에서 함께 쓰는 버튼·링크에는 기존 brand-400을 적용해 3:1 이상 대비를 유지한다. 클릭 피드백은 기존 reduced-motion 대응을 유지한다.

## 화면 구조

```text
상품 탐색                      짧은 수집 안내
┌ 검색어 / 세트 번호 ───────────────── 검색 ┐
│ 카테고리 │ 상태 │ 정렬 │ 최소가 ~ 최대가 │
└ 적용된 조건 × · 조건 ×      필터 초기화 ┘
검색 결과 N개 ────────────────────────────
세트 바로가기(해당할 때)
사진       사진       사진       사진
식별·제목  식별·제목  식별·제목  식별·제목
가격·상태  가격·상태  가격·상태  가격·상태
```

모바일에서는 검색을 먼저 두고 상세 필터를 접는다. 펼친 필터는 두 열, 가격 범위는 한 행 전체를 쓴다. 큰 필터를 sticky로 고정하지 않아 작은 화면의 결과를 가리지 않는다. 적용 조건은 모든 폭에서 읽고 제거할 수 있다.

## FSD 경계

- `shared/ui`: 입력·선택·장문 입력의 공통 상태 스타일, 버튼의 로딩 상태, 서버 화면 새로고침 버튼. 도메인 규칙은 넣지 않는다.
- `features/listing-filter/model`: 검색값 정규화·주소·가격 오류·적용 칩 규칙. 서버 뷰도 공개 API로 같은 규칙을 쓴다.
- `features/listing-filter/ui`: 반응형 필터와 접근 가능한 자동완성. React transition으로 탐색 상태를 표시한다.
- `entities/listing/ui`: 카드의 비교 위계와 거래 상태 고지.
- `views/search`: 조회 실패/빈 결과/정상 결과 조합. 잘못된 가격 범위는 API 호출 전에 차단한다.

자동완성 요청은 기존 300ms 지연과 늦은 응답 무효화를 유지한다. 결과의 검색어와 현재 입력이 같고 입력에 포커스가 있을 때만 목록을 연다. 검색 완료 후 주소가 바뀌면 기존 key로 초안을 초기화한다.

## 검증

저장소 Playwright에서 URL 보존·범위 검증·키보드 선택·조건 제거/뒤로 가기·반응형/초점·실제 목록/상세 회귀를 검사한다. 브라우저 모킹은 카탈로그 지연·오류 같은 재현에만 사용하며 실제 백엔드 읽기 검증과 구분한다. 수동 검수는 독립 Orca 탭, 자동 검증은 기존 Playwright를 쓴다. 3000/8090 서버는 유지한다.
