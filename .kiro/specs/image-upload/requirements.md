# 이미지 업로드 (MinIO) — 요구사항

## 개요

판매자가 **직접 촬영한 사진**을 실제로 업로드할 수 있게 한다(IP 안전 정책: 공식 이미지 금지).
호스트의 MinIO(S3 호환)를 사용한다. 단, MinIO S3 API(9000)는 외부에 공개돼 있지 않으므로
업로드/서빙은 백엔드를 경유한다(같은 오리진 `gole.kscold.com`).

## 요구사항

### R1. 업로드
- **R1.1** 인증 사용자는 이미지 파일(jpg/png/webp)을 업로드할 수 있다.
- **R1.2** 최대 용량 제한(예: 8MB)과 이미지 MIME 타입만 허용(검증). 그 외 거부.
- **R1.3** 업로드 결과로 우리 도메인 기준의 **서빙 URL**을 반환한다(`/api/v1/uploads/{key}`).

### R2. 서빙
- **R2.1** 업로드된 객체는 `GET /api/v1/uploads/{key}`로 스트리밍 제공한다(브라우저 접근 가능, 동일 오리진).
- **R2.2** 적절한 Content-Type/캐시 헤더 설정.

### R3. 저장소
- **R3.1** MinIO `gole` 버킷에 저장. 키는 충돌 없는 무작위(UUID + 확장자).
- **R3.2** 설정은 환경변수(엔드포인트/자격증명/버킷). 미설정 시 기능 비활성(명확한 오류).

### R4. 판매 등록 연동
- **R4.1** 판매 등록 폼의 사진 입력을 **URL 입력 → 파일 업로드**로 교체. 업로드 후 반환 URL을 매물 사진으로 사용.
- **R4.2** 최소 1장(기존 도메인 불변식 유지). 공식 이미지 금지 안내 유지.

## 비범위
- 이미지 리사이즈/썸네일/EXIF 제거 — 후속.
- presigned URL 직접 업로드(현재 S3 API 미공개라 백엔드 프록시) — 인프라 공개 시 전환.
- 다중 이미지(현재 대표 1장) — 후속.

## 보안/정책
- MinIO 자격증명은 백엔드 환경변수로만(프론트 노출 금지).
- 업로드는 인증 세션 필요(후속: 가드). 개발 단계에서는 우선 동작 우선.
- IP 정책: "직접 촬영 사진만" 안내를 업로드 UI에 명시.
