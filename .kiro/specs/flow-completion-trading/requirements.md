# 거래 흐름 보완 요구사항

- R1. PR245의 입찰 원자성, 유효 수락 제안 선택 유지, 직거래 확인·초대 동작을 보존한다.
- R2. 예약 중 매물은 거래완료와 구분한다. 구매·거래가 진행 중임을 알리고 기존 주문·대화로 돌아갈 수 있게 한다.
- R3. 구매자는 결제 대기 주문의 취소를 명시적으로 확인할 수 있다. 판매자·다른 구매자는 취소할 수 없다.
- R4. 취소 전 PG 원장을 확인한다. 결제 없음 또는 최종 실패만 취소하고, 승인·진행·검토·조회 장애는 예약을 보존한다. 취소와 매물 예약 복원은 원자적이며 반복 취소는 멱등이다.
- R5. 취소와 승인 경합에서 자금을 잃지 않는다. 취소 뒤 늦게 승인된 결제는 환불 대상으로 보존하며 이미 해제한 매물이나 다음 주문의 예약을 건드리지 않는다.
- R6. 주문 화면의 결제 시작 직전에 최신 주문·공개 상태를 확인한다. 이미 결제·취소된 주문으로 결제창을 다시 열지 않는다.
- R7. 배송 현황은 완료 뒤에도 거래 당사자가 확인할 수 있고, 발송 전 화면에서 최신 배송 상태를 재조회할 수 있다.
- R8. 공통 모달과 Tailwind UI를 사용한다. 결제·공개 잠금을 유지하고 실제 결제와 외부 메시지를 보내지 않는다.
- R9. 별도 E2E 환경에서 실제 주문 API와 회귀 테스트를 검증한다. 사용자 프리뷰 3000/API8090은 읽기 전용으로 보존한다.
