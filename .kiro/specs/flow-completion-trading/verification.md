## 환경과 남은 검증 한계

- 쓰기 검증은 감독자가 준비한 WEB3002/API8080·별도 E2E DB와 시드 계정만 사용한다. 사용자 프리뷰3000/API8090에 쓰지 않았다.
- 브라우저 UI는 기존 Playwright 회귀와 독립 Orca 내장 탭을 구분해 검증한다. 스토어 심사용 계정 검증이 아니다.
- PG는 E2E 스텁이다. 실제 PortOne 승인·취소, 외부 메시지 전송, 실배송 추적 업체, 운영 데이터는 실행하지 않는다.
- 직거래 완료 API의 단계1 실제 브라우저 왕복은 별도로 실행하지 않았다. 기존 직거래 UI 회귀와 감독자의 서비스·Mongo 동시성 통합 검사로 구분해 검증하며, 결제 단계 E2E 설정을 임의 변경하지 않았다.
- 운영 결제·공개 잠금은 유지한다. 감독자가 취소 API를 기존 거래 후속 조치로 분류하고 관리자 취소 상태 표시를 통합한다.
- 취소 주문은 지연 승인 증거 때문에 문의 파기의 종결 상태로 보지 않는다. PG 취소가 최종적으로 불가능해지는 시점에 따른 별도 보존 기한 정책은 이번 변경에 추정으로 추가하지 않는다.
- worker는 서버를 시작·종료하지 않았다. 서버와 원격 dev 반영, 팀 볼트 기록 및 공유 체크아웃 보존은 감독자가 관리한다.
