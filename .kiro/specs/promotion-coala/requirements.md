# 홍보 기억과 제한된 액션 파이프라인

1. 시멘틱 지식(KNOWLEDGE), 반려 경험, 프로시듀얼 지침(PROCEDURE)과 파일 절차를 구분해 단계별 작업 기억을 만든다. 기존 MongoDB/러너/gateway를 재사용한다.
2. 관리자는 코드로 검토된 브랜드 색·옆모습 고래·고래×브릭 컨셉을 초기 제안으로 등록한다. 다른 관리자가 확정하며 재등록은 기존 변경을 덮어쓰지 않는다.
3. 분류에 해당하는 활성 지침을 실행 시작에 모두 조회해 고정한다. 기획/제작 단계별 대상만 적용하고 관련 반려 사례는 최대 3건씩 전달한다.
4. 모델은 단계 안에서 생성 여부·화면·문구를 결정한다. 조회·캡처·제출·실행 순서는 러너가 결정하며 임의 명령/파일 경로를 모델에서 받지 않는다.
5. Claude가 이미지별 최대 40자/두 줄의 문구를 만들고 Codex는 imagegen 스킬로 그 문구와 실제 모바일 화면을 꾸민다. 서비스/기능 홍보 모두 로열블루 브릭·모바일 기본 절차를 사용한다.
6. 원본/최종 이미지, 스타일 ID/버전, 문구, 실제 프롬프트와 단계별 사용 기억을 관리자 검토 자료에 남긴다. 제작 실패는 원본 사용으로 명확하게 표시한다.
7. 390×844 실제 모바일 캡처를 사용한다. 형식 버전이 없는 데스크톱 캡처는 재사용하지 않는다.
8. 6,000자 편집 지시문 상한은 유지하고 초과 시 구성별 길이를 비공개 원장에 기록한다. 지침을 임의 삭제/절단하지 않는다. 과거 문서는 기본값으로 호환하며 파괴적 마이그레이션을 하지 않는다.
