# Mobile Splash Requirements

## 배경 (2026-10-11)

- 사용자 요청: **고레 RN 스플래시 화면을 예쁘게 만들어 실제 적용.**
- 지금 스플래시(`expo-splash-screen`)는 파란 배경(`#1D4ED8`) 위 흰 고래를 `imageWidth 76`으로 그려 고래가 너무 작다.
  또 루트 레이아웃이 마운트되자마자 스플래시를 내려, 파란 화면 → 흰 화면 + 스피너 → 웹 화면 순으로 두 번 바뀐다.
- 사용자 교정 정본: **얼굴 왼쪽·꼬리 오른쪽인 옆모습 브릭 고래**, 검은 작은 눈·미소, 로열블루 몸·밝은 윗면·가운데 골드 스터드.
  정면 재디자인은 하지 않는다.

## 요구사항

### R1. 그림

1. 흰 배경 위에 **정본 색 그대로의 옆모습 고래**(`apps/web/src/shared/ui/logo/mark.svg`의 다섯 경로와 색)를 충분히 크게 그린다.
2. 고래 아래에 `GoLe` 워드마크를 둔다. 웹 로고처럼 `Go`는 짙은 남색, `Le`는 브랜드 파랑이다. 글꼴 렌더링에 기대지 않는
   벡터 경로라 어느 머신에서 생성해도 같은 PNG가 나온다.
3. 산출물은 `scripts/build-brand-icons.mjs`가 정본에서 결정론적으로 만든다. 앱 아이콘·Android 아이콘·알림 아이콘·웹 마스코트·
   favicon은 바꾸지 않는다.

### R2. 플랫폼 제약

1. Android 12+ 스플래시는 288dp 캔버스의 아이콘을 지름 192dp 원으로 자른다. 고래와 워드마크의 모든 불투명 픽셀이
   중심에서 **94dp 이내**여야 하고, 생성기가 실측해 넘으면 멈춘다.
2. iOS는 같은 그림을 같은 크기(288pt)로 가운데 둔다. 두 플랫폼의 첫 인상이 같다.
3. 다크 모드에서도 흰 배경이다(별도 다크 그림을 두지 않는다).

### R3. 시작 흐름 — 깜빡임은 줄이고 지연·가짜 진행률은 없다

1. 네이티브 스플래시는 **첫 웹 화면이 실제로 그려졌을 때**(첫 WebView 로드 완료) 내린다. 그 전에 실패 화면(오프라인·오류)이
   뜨면 바로 내린다.
2. 웹이 늦어도 스플래시가 화면을 붙잡지 않게 **상한 3초** 뒤에는 내린다. 이후는 지금처럼 WebView 로딩 표시가 이어진다.
3. 진행률·인위적인 대기·애니메이션 지연을 넣지 않는다.
4. 웹이 아닌 첫 화면으로 들어와도(딥링크 등) 상한 뒤에는 반드시 내려간다.

## 수용 기준

- `node scripts/build-brand-icons.mjs` 재실행이 같은 파일을 만들고, 스플래시 최원점 실측이 94dp 이하로 출력된다.
- iOS 시뮬레이터 네이티브 빌드에서 흰 배경·큰 파란 고래·워드마크 스플래시가 보이고, 첫 웹 화면으로 바로 이어진다.
- mobile typecheck·lint·format, core 테스트, `expo export` 통과. Expo Go 실행만으로 네이티브 스플래시를 검증했다고 하지 않는다.
- 새 스플래시는 네이티브 자산이라 **새 EAS 빌드**가 필요하다(OTA 없음).
