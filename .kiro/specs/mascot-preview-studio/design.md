# 설계

## 시각 방향

성인 브릭 수집가를 위한 차분한 마켓에 작은 장난기를 더한다. 흰 면·얇은 구분선·코발트 선택 표시를 사용하고 골드는 고래의 가운데 스터드에 집중한다. 제목은 SUITE, 안내·폼은 SUIT를 유지한다. 카드 안에 카드를 반복하기보다 미리보기, 후보, 적용, 이력을 구획한다.

새 후보는 옆모습의 브릭 구조를 살리고 큰 흰 눈 대신 작은 눈·부드러운 미소·간결한 꼬리를 사용한다. 정면 얼굴이나 실제 레고 상표를 넣지 않는다. 명시적인 새 키로 등록해 기존 선택과 저장된 이력을 보존한다.

후보는 `side-brick-mellow`(말랑 브릭 고래)다. `mascot-concept-2026-10-26.png`는 내장 imagegen으로 생성한 형태 검토용 시안이고, 제품에서는 `shared/ui/logo/presets/side-brick-mellow.tsx`의 SVG를 사용한다. 시안의 래스터 질감은 사용하지 않고 기존 색상 토큰과 inverse 톤을 받는 네이티브 벡터로 정리했다. 분수는 브릭 세 개를 정지 상태로 그려 반복 움직임을 추가하지 않는다.

생성 프롬프트의 핵심 조건: 왼쪽 얼굴·오른쪽 꼬리의 옆모습, 둥근 직사각형 브릭 몸·밝은 윗면·스터드 세 개, 가운데 골드, 작은 남색 눈과 작은 미소, 자연스럽게 연결된 꼬리. 투명 배경, 텍스트·그라데이션·그림자·정면 얼굴·큰 흰 눈 제외. 참조는 기존 `.kiro/specs/brand-icon/side-whale-2026-10-09-compare.png`의 옆모습 정체성이다.

## 책임 분리

- `packages/core/src/mascot`: 후보 키·이름·설명. API 도메인 `MascotPresets`와 일치시킨다.
- `shared/ui/logo/presets`: 벡터 그림. 기존 `Logo`의 크기·톤·접근성 계산을 재사용한다.
- `views/admin-mascot`: 후보/미리보기/적용의 화면 조합. 선택 상태와 적용 상태를 분리하고 작은 컴포넌트로 나눈다.
- 기존 업로드와 적용 API, 서버 저장/감사 계약은 그대로 사용한다. 새 키 허용 외에 저장 모델을 변경하지 않는다.

## 화면과 상태

선택 미리보기 → 후보 목록 → 사유와 확인을 포함한 적용 → 업로드/이력 순서로 읽히게 한다. 넓은 화면은 비교 대상과 조작을 함께 볼 수 있게 배치한다. 작은 화면의 후보 전환이 미리보기를 찾기 위한 긴 왕복 스크롤을 요구하지 않게 한다.

저장 도중에는 선택 버튼을 비활성화한다. 다른 후보를 고르면 검토 확인을 초기화한다. 실제 적용은 서버 응답을 받은 뒤에만 전역 마스코트 갱신 이벤트를 보낸다. 충돌 시 새 서버 리비전을 읽고 사용자에게 다시 검토하도록 안내한다.

## 스킬과 분담

`frontend-design`으로 방향을 정하고 `hallmark`의 감사 지침과 `web-design-guidelines`로 검토한다. 공식 Vercel `vercel-composition-patterns`를 설치해 미리보기와 후보 조합에 적용한다. root는 스펙·벡터/코어/API·문서·Git, 다른 Codex는 `views/admin-mascot/**`와 해당 E2E를 맡는다. 공유 체크아웃에서 파일 소유권을 겹치지 않는다.
