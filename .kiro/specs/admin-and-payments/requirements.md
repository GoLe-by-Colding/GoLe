# 관리자 · 결제 (Admin & Payments) — 요구사항

> 소급 작성된 스펙. 이미 구현·배포된 기능을 SDD 형식으로 문서화한다.

## 개요

운영자(관리자)가 플랫폼 데이터를 관리할 수 있는 권한 기반(RBAC) 관리자 기능과,
포트원(PortOne) 기반 실결제 연동. 선행 조건으로 "실제 검증되는 인증 세션"이 필요하다.

## 배경 / 문제

- 기존 인증은 로그인 시 무작위 토큰만 발급할 뿐 **검증/저장되지 않아** 서버가 호출자를 식별하지 못했다.
- 계정에 **권한(role) 개념이 없어** 관리자/일반 구분이 불가능했다.
- 결제는 항상 성공하는 **스텁**이었다.

## 요구사항

### R1. 인증 세션 (선행)
- **R1.1** 로그인 성공 시 세션 토큰을 발급하고 토큰→(계정,권한)을 **Redis에 저장**한다(TTL 7일).
- **R1.2** `GET /api/v1/accounts/me`는 `Authorization: Bearer <token>`로 현재 계정/권한을 반환한다. 유효하지 않으면 401.

### R2. 권한 (RBAC)
- **R2.1** 계정은 `USER` 또는 `ADMIN` 권한을 가진다. 신규 가입은 USER.
- **R2.2** 관리자 계정은 환경변수(`GOLE_ADMIN_EMAIL`/`GOLE_ADMIN_PASSWORD`)로 부트스트랩한다(멱등, 인증완료 상태).

### R3. 관리자 API (`/api/admin/**`)
- **R3.1** 모든 `/api/admin/**`는 ADMIN 권한 토큰만 통과(없으면 401, USER면 403).
- **R3.2** 대시보드 집계: 컬렉션별 도큐먼트 수(`GET /api/admin/overview`).
- **R3.3** 카탈로그 세트 목록/등록(`GET`·`POST /api/admin/catalog/sets`).

### R4. 관리자 프론트
- **R4.1** 로그인 세션에 권한을 저장하고, ADMIN일 때만 헤더에 관리자 진입점 노출.
- **R4.2** `/admin`은 비로그인/일반 사용자에게 접근 안내(차단)하고, ADMIN에게 대시보드(현황+카탈로그 관리)를 제공.

### R5. 포트원 결제
- **R5.1** 결제는 프론트 브라우저 SDK가 수행하고, **서버가 결과를 검증**한다(verify-on-server).
- **R5.2** 우리 주문 id를 포트원 `paymentId`로 사용하여, 결제 승인 시 서버가 결제 상태(PAID)와 금액 일치를 확인한다.
- **R5.3** 설정(`portone.enabled` + 자격증명) 시에만 활성, 미설정 시 스텁으로 동작한다.

## 비범위
- 관리자의 매물/주문/회원/게시글 모더레이션(정지·강제삭제) — 후속.
- 비밀번호 변경/재설정 UI — 후속.
- 결제 수단 다양화(가상계좌/간편결제 등) — 후속.

## 보안 고려
- 관리자 비밀번호는 저장소(repo)에 커밋하지 않는다(환경변수 + Mongo 해시).
- 포트원 API secret은 백엔드 환경변수로만 보관(프론트 노출 금지). storeId/channelKey만 프론트 공개.
- 세션 토큰은 256비트 난수(opaque) + Redis 저장. (후속: httpOnly 쿠키 전환 고려)
