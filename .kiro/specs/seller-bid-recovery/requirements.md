# 판매자 입찰 조회 복구

## 확인한 문제

- 판매 중인 세트 매물에서 입찰 조회가 실패하면 `SellToBidSection`이 `null`을 반환한다. 판매자는 입찰 없음과 조회 실패를 구분하거나 다시 조회할 수 없다.
- 판매 수락이 충돌한 뒤 자동 입찰 재조회도 실패하면 구획이 사라져 최초 판매 실패 이유까지 잃는다.
- 판매가를 올리는 버튼은 금액을 포함한 긴 문구에 공통 버튼의 줄바꿈 금지가 적용돼 320px에서 구획 밖으로 31px 넘쳤다. 버튼 너비만 제한하면 문구가 양옆으로 잘리므로 텍스트 영역도 함께 검증한다.

## 요구사항

- R1. 거래가 허용된 판매 중 세트 매물에서는 조회 중·조회 실패·입찰 없음·입찰 있음 상태를 구분한다. 세트 번호 없는 매물, 세트 이외 카테고리, 판매 중이 아닌 매물에는 기존대로 입찰 행동을 노출하지 않는다.
- R2. 첫 조회나 재조회 실패 시 이유와 `입찰 다시 확인` 버튼을 제공한다. 재시도 중에는 이전 입찰 가격으로 판매할 수 없고 중복 조회도 막는다.
- R3. 판매 수락 실패 문구는 이후 입찰 재조회 실패·빈 응답에도 유지한다. 최신 유효 가격을 읽은 뒤 사용자가 다시 확인 모달을 거쳐 판매한다.
- R4. 실패 시의 재조회는 GET만 수행한다. 판매가 변경·입찰 수락은 사용자가 확인한 한 번의 기존 원자적 fill 요청으로만 처리한다.
- R5. 최고 입찰가, 현재 판매가, 판매 행동을 읽기 쉬운 순서로 보여 준다. 320·375·414·768px에서 긴 한글과 최대 입찰 금액이 가로로 넘치지 않으며 버튼은 터치 가능한 높이를 유지한다.
- R6. 수락 성공 시 실제 응답의 입찰가와 수락 제안 안내를 유지한다. 거래 완료나 결제 완료로 표현하지 않는다.

## 보존 경계

- PR245의 원자적 판매가 변경·입찰 수락, 본인 입찰 제외, 가격 충돌 처리, 수락 제안 갱신을 보존한다.
- 공통 Tailwind 버튼·확인 모달을 사용하고 `alert`를 추가하지 않는다. 브랜드 토큰·공개/결제 설정·서버/API 계약은 변경하지 않는다.
- 기존 사용자 Web3000/API8090은 읽기 전용으로 보존한다. 쓰기 동작 회귀는 별도 테스트 웹에서 API 요청을 가로채고, 실제 쓰기가 필요하면 격리 E2E 환경만 사용한다.
