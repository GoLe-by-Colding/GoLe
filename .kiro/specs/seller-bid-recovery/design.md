# 설계

## 상태와 요청

- 입찰 스냅샷을 `ready(row)` 또는 `error`로 구분하고 세트·상태 키 및 조회 순번을 함께 보관한다.
- 현재 키·순번에 해당하는 결과가 없으면 `loading`이다. 새 조회를 시작하면 과거 가격으로 판매할 수 없게 하며, AbortController로 지난 요청을 취소한다.
- 성공한 빈 호가창은 정상 `ready` 상태이며 실패와 다른 안내를 제공한다. 조회 실패는 구획을 지우지 않는다.
- 판매 오류와 입찰 조회 상태는 분리한다. 판매 실패 문구는 재시도 중에도 유지하며, 새 판매 시도나 성공 응답에서만 정리한다.
- 기존 `fillBid(setNumber, listing.id, targetPrice?)`와 확인 모달을 유지한다. 재조회 버튼은 fill을 재전송하지 않는다.

## 화면 컨셉

성인 브릭 거래자가 현재 입찰 가격을 비교하고 수락 여부를 판단하는 판매자 영역이다. 수치 장식 대신 상품의 세트 번호·상태·실제 가격을 중심에 둔다.

- 색: 흰 바탕 `#FFFFFF`, 행동 `brand-600 #1D4ED8`, 보조 바탕 `brand-50 #EFF4FF`, 본문 `neutral-900 #18181B`, 경계 `neutral-200 #E4E4E7`. 오류만 기존 danger 의미색을 쓴다.
- 글꼴: 제목 SUITE(`font-display`), 설명·금액·버튼 SUIT(`font-sans`). 금액은 `tabular-nums`와 줄바꿈 금지를 적용한다.
- 배치: 왼쪽 정렬, 제목/세트 상태 → 입찰 수와 최고가 → 판매가 차이 안내 → 주 행동/보조 행동 순서다. 모바일은 행동을 세로로 배치하고 긴 문장은 어절 단위로 줄바꿈한다.
- 구획 안의 요소별 카드를 반복하지 않고 금액과 다음 행동에만 위계를 둔다. 공통 버튼을 재사용하되 이 구획의 긴 문구에 맞춰 자동 높이·줄바꿈을 허용한다.

```text
구매 입찰
#세트 · 상품 상태

입찰 N건 · 최고 입찰가
금액
현재 판매가와 차이 / 수락 후 안내
[주 판매 행동 — 좁은 화면에서는 줄바꿈]
[현재 판매가를 유지하는 보조 행동]
```

조회 실패 시 같은 위치에 실패 안내와 재시도를 보여 준다. 로딩은 상태 문구와 공통 Skeleton으로 알리고, 확인되지 않은 금액은 행동에 재사용하지 않는다. 기존 브랜드와 판매자 패널에 맞추므로 추가 로고·일러스트·그라데이션은 필요하지 않다.

공통 Button은 `whitespace-nowrap`을 갖고 클래스 조합 함수는 충돌을 제거하지 않는다. 같은 요소에 `whitespace-normal`을 덧붙여도 CSS 출력 순서에 따라 글자가 잘릴 수 있으므로, 버튼 안의 별도 `span`에 줄바꿈을 적용한다. 자동 높이와 최소 44px을 유지하고 Range로 실제 텍스트 상자가 버튼 안에 들어오는지도 검증한다.

## 변경 경로와 검증

- `apps/web/src/features/manage-listing/ui/sell-to-bid-section.tsx`: 상태 및 표시/행동 복구.
- `apps/web/tests-e2e/buy-bids.spec.ts`: 초기 실패→재실패→복구, 판매 충돌→조회 실패, 최신 가격 재확인, 빈 입찰, 좁은 화면 회귀.
- `.kiro/specs/seller-bid-recovery/`: 요구사항·설계·실행 근거.

기존 실제 API가 렌더하는 시드 상세를 사용하되 브라우저의 입찰 조회/판매 요청은 가로챈다. 사용자 프리뷰와 분리한 웹·캐시에서 실패 재현과 수정 후 통과를 비교하고 Orca 독립 탭에서 화면·키보드·반응형을 확인한다. API/core 변경은 필요하지 않다.
