# 설계

## 의존성과 경계

Zod 기본 엔트리는 보안 수정된 4.6.7로 통일한다. ESLint React Hooks는 기존 Zod 4 API를 그대로 사용한다. Expo CLI 57.0.28, Steiger 0.7.0, zod-validation-error 3.5.4는 Zod 3 API를 요구하므로 공개 호환 엔트리 `zod/v3`로 import만 좁힌다. 버전 숫자를 바꾸는 것으로 호환 엔트리의 취약점이 해결되었다고 판단하지 않는다.

Zod 4 패키지에 포함된 v3 구현의 배열·집합 상한 검증을 원소 순회보다 앞에서 종료하도록 보강한다. 기존 too_big issue의 경로·문구·상한을 유지하고, `.length()`의 하한 실패는 기존 동작을 유지한다. 소스와 배포 ESM/CJS를 함께 패치하며 pnpm patchedDependencies로 고정한다. v3 Map에는 크기 제한 API가 없으므로 새로운 제한을 추가하지 않는다.

## 검증

기존 Playwright Node 계약 테스트에 안전한 1,000개 입력을 사용한다. 상한 초과 때 원소 refinement 방문이 0인지, 정상·하한·원소 오류 결과가 유지되는지 확인한다. 실제 Steiger 설정 검증·오류 포매터와 Expo 개발 도구 스키마도 호출해 서로 다른 Zod 오류 클래스나 v4 API 변경으로 생기는 실패를 잡는다. 사용자 서버에는 쓰기 요청을 보내지 않는다.

상위 도구가 Zod 4 API로 이전하면 소비자 import 패치를 제거한다. v3 호환 엔트리의 상한 처리가 upstream에 반영되면 해당 패치도 테스트를 유지한 채 제거한다. 감사 예외나 CI 조건은 변경하지 않는다.
