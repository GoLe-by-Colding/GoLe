# 브릭 필터 웹 경계 보완

기준: 기존 `README.md`, `requirements.md`, `design.md`의 Java 원장·인증·멱등성 계약을 유지한다. 이 문서는 2026-09-13 웹 검토에서 구체화한 보완 범위와 구현 결과다.

## 요구사항

- 5xx/네트워크 timeout으로 접수 여부가 불확실하면 새 멱등키를 발급하지 않는다. 상태 조회의 404 뒤에만 동일 키·사진·모드 재전송을 제공한다.
- 조회에도 유한 deadline을 적용하고 자동 polling은 이전 조회가 끝난 뒤 다음 조회를 예약한다.
- 종료된 작업을 뒤늦은 RESERVED 조회가 되돌리지 못하게 한다. 계정별 Editor의 기존 key 경계를 유지한다.
- 잘못된 사진 선택은 이전의 유효한 사진과 동의를 제거한다. 결과는 인증 fetch의 PNG signature·MIME·8MiB 상한을 검증한 바이트만 blob URL로 표시한다.
- 이용 횟수·활성화·재시도 가능 여부는 서버 응답을 표시하며 웹 원장을 만들지 않는다. 401은 재로그인을 안내하고 생성을 차단한다.
- 상품/게시글 폼은 업로드 도중 키보드 제출, 같은 렌더의 중복 제출·파일 이벤트를 막고 실패 후 재시도를 허용한다.

## 설계와 구현

- core brick-filter 전용 request 함수에서 쿠키·기존 bearer 지원, no-store, GET 15초/POST 180초 deadline, 구조가 잘못된 오류 응답의 안전한 fallback을 통일했다. 뒤늦은 401이 다른 계정의 세션을 지우지 않도록 이 API에서는 공유 세션을 직접 삭제하지 않는다.
- Editor는 ref로 동기 요청 잠금과 quota refresh 세대를 관리한다. 401은 진행 중인 오래된 refresh도 무효화한다. 자동 polling은 재귀 setTimeout이며 cleanup/active guard로 해제된 작업의 응답을 폐기한다.
- 자동·수동 상태 응답 모두 동일 id의 종료 상태를 RESERVED로 되돌리지 않는다. 생성 성공과 후속 quota 갱신 실패는 별도 메시지로 처리한다.
- 업로드 폼 ref 잠금은 setState의 다음 렌더 전에도 유효하다. 성공 후 화면 전환 전까지 제출 잠금을 유지하며 실패에서만 해제한다. 업로드 상태에는 role=status를 제공한다.

## 검증과 남은 범위

실행 결과와 정확한 파일 묶음은 `web-verification.md`, 재현 스크립트는 `web-*-tests.cjs`와 `web-browser-check.py`를 따른다. 실제 OpenAI 호출, Java 원장 경쟁 검증, HEIF 디코딩은 이 웹 검토의 검증 범위가 아니다. 페이지를 떠나거나 새로고침한 뒤의 불확실한 요청 키 복구는 브라우저 저장소에 추가하지 않았으며 기존 서버 작업 목록과 quota 조회를 유지한다.
