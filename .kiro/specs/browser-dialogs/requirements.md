# Browser Dialogs Requirements

## 배경 (2026-10-11)

- 사용자 지시: **프론트에 `alert`·`confirm`·`prompt`가 있으면 안 되며 모두 앱 공통 모달로 바꾼다.**
- 2026-10-11 기준 `apps/web/src`에 브라우저 기본 대화상자 호출이 14곳 있었다(커뮤니티 댓글, 관리자 마스코트, 계정 보안,
  관리자 정산·회원 탈퇴, 부품 요청 관리, 게시글 관리, 입찰가 즉시 판매). 기본 대화상자는 브랜드 화면과 따로 놀고, 문구 줄바꿈·
  입력 검증·선택지를 줄 수 없으며, 웹뷰·자동화에서 막히거나 자동으로 닫힌다.

## 요구사항

### R1. 공통 모달

1. `shared/ui`에 확인(confirm)·안내(alert)·입력(prompt, 선택지 포함) 세 가지를 띄우는 공통 모달을 둔다. 스타일은 Tailwind className만 쓴다.
2. 호출부는 `await`로 결과를 받는다 — 확인 `true/false`, 입력 문자열/`null`(취소), 안내는 닫힐 때 끝난다.
3. 열리면 첫 초점을 안전한 버튼(위험 조치는 취소, 그 외는 확인, 입력은 입력란)에 두고, Tab은 모달 안에서만 돈다.
   Escape·바깥 클릭·취소는 모두 "취소"다. 닫히면 연 버튼으로 초점을 돌려준다. 열린 동안 뒤 화면은 스크롤되지 않는다.
4. 한 화면에서 모달이 이미 열려 있으면 새 요청은 즉시 취소로 끝난다(중복 요청 방지). 화면이 사라지면 열린 요청은 취소로 끝난다.
5. `window.alert/confirm/prompt`를 다시 정의하는 우회는 하지 않는다. eslint `no-alert`로 다시 들어오는 것을 막는다.

### R2. 호출부 교체 — 동작 보존

1. 확인을 취소하면 아무 요청도 보내지 않는다. 확인하면 정확히 한 번 보낸다. 기존 진행 중(busy) 표시·중복 클릭 차단은 그대로다.
2. 관리자 회원 탈퇴의 **요청 ID 입력 확인**은 그대로 정확히 같은 값만 통과한다. 다르면 모달 안에 이유를 보이고 닫지 않는다.
   보존 사유는 허용된 코드 3개 중에서 고른다(자유 입력 없음).
3. 관리자 정산의 **실이체 확인 문구**("외부 이체가 실제 완료됐나요? …" 등)와 회원 탈퇴의 **연계 파기 검토 문구**는 그대로 둔다.
4. 회원 탈퇴 접수 뒤 요청 ID 안내는 모달로 보여 주고, 확인하면 지금처럼 `/login?deletionRequested=1`로 간다.

## 수용 기준

- `rg "\b(window\.)?(alert|confirm|prompt)\(" apps/web/src` 결과 0건, `pnpm --filter web lint`가 `no-alert`를 강제한다.
- E2E: 취소 시 mutation 0건, 확인 시 1건, 요청 ID 불일치는 거부되고 요청 없음, 브라우저 기본 대화상자 0회.
