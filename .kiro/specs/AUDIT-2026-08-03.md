## 실제로 남은 작업 (우선순위)

### P0 — 보안·데이터 정합성
1. **미디어 업로드에 인증이 없다.** `MediaController`의 `POST /api/v1/media/images`와
   `/images/batch`에 세션 검증·레이트리밋이 전혀 없다(관련 심볼 0건).
   현재 공개된 프로덕션에서 누구나 무제한 업로드가 가능하다. → `image-upload` N1
2. **e2e가 개발/운영 DB에 직접 쓴다.** 로컬 `listings`에 `{title:"환불검증", price:0,
   sellerId:"s", photoUrls:["a.jpg"]}` 같은 테스트 잔여물이 실매물과 섞여 있다.
   `t`/`t2`/`txncheck` 테스트 컬렉션도 잔존. → `storefront-and-presentation` 후속

### P1 — 배포 리스크
3. **Mongo 인덱스 이름 충돌.** `FollowDocument.java:13`은 `uq_follower_seller`를 선언하는데,
   기존 DB에는 동일 키의 구 인덱스 `uniq_follow`가 남아 있다. Spring Data가
   `IndexOptionsConflict(85)`로 부팅에 실패한다 — **애플리케이션이 아예 안 뜬다.**
   로컬은 구 인덱스를 드롭해 해결했으나, 같은 이력을 가진 배포 DB에도 동일 조치가 필요하다.
   ```
   db.follows.dropIndex("uniq_follow")   // 앱이 새 이름으로 재생성
   ```

### P2 — 로컬 개발 환경
4. **`docker-compose.yml`에 MinIO가 없다.** `image-upload` 스펙 전체가 MinIO 전제인데
   compose에는 mongo/redis만 있다. `pnpm infra:up` 후 `MediaSeeder`가 전부 실패하고
   (`UnknownHostException`) 로컬은 이미지가 깨진 채로 개발하게 된다. → `image-upload` L1
5. `storage.s3.endpoint` 기본값이 `host.docker.internal:9000`이라 호스트 직접 실행 시
   해석되지 않는다. → `image-upload` L2

### P3 — 기능 미완
6. `condition-disclosure` 등급 5단계 확장(R1.1/R1.2). `ItemCondition`이 구 3단계 그대로이고
   `ItemGrade`·`LIKE_NEW`·`USED_GOOD`·`USED_FAIR`·`DAMAGED` 심볼이 코드에 없다.
   누락노트 불변식 테스트와 고지 필드 e2e 단언도 없다.
7. `lego-marketplace` 13.5 알림 트리거 확장(팔로우 셀러 신규 매물, 위시리스트 가격 변동).
   현재 트리거는 `ORDER_PLACED` 1종뿐.
8. `design-system` T7 다크 모드, T8 토스트, T10 폼 검증 공통화, T11 카탈로그, T12 브랜드 아이콘.
9. `admin-and-payments` 비밀번호 변경/재설정, 포트원 라이브 검증.
