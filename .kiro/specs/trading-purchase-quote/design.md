# 구매 금액 확인 설계

## 확인한 결함

`PurchaseButton`은 `useListingOffers().offers === null`을 빈 배열처럼 사용한다. 이때 구매하기를 누르면 `selectedOffer=null`이 고정되고, 늦게 도착한 수락 제안이 있어도 `offerId` 없이 주문한다. `OrderService.agreedAmount`는 제안 ID가 없으면 예약한 매물가를 쓰므로 실제로 할인 합의가 누락된다. 조회 실패도 같은 경로로 이어진다.

## 상태와 행동

로그인한 타인 매물의 구매자는 제안 조회 성공과 현재 시각 준비를 기다린다. 조회 중에는 비활성 확인 버튼과 상태 안내, 실패하면 오류와 다시 확인 버튼을 표시한다. 실패 상태가 연락처 입력 중 발생하면 폼을 유지하되 제출을 막는다. 명시적 재조회에 성공하면 입력한 연락처와 선택한 제안으로 계속한다.

정가 주문 직전에 수락 제안이 새로 확인되면 금액을 제안가로 갱신하고 제출하지 않는다. 새 금액을 확인한 다음 제출에서 해당 제안 ID를 보낸다. 기존에 선택한 제안이 유효하면 먼저 선택한 제안을 유지한다. 만료·409 거부 뒤 정가 확인과 남은 제안 선택은 기존 계약을 보존한다.

## 화면 컨셉

수집가가 거래 조건을 차분하게 확인하는 짧은 구매 확인서다. 흰 배경 `#FFFFFF`, 따뜻한 중립색 `#18181B`, 경계 `#E4E4E7`, 코발트 `#1D4ED8`, 옅은 브랜드색 `#EFF4FF`만 사용한다. 제목은 기존 SUITE, 금액·설명·폼은 SUIT를 유지한다. 금액은 왼쪽 정렬과 숫자 자릿수 정렬로 읽기 쉽게 만든다.

```text
주문 금액                       [적용 제안 안내]
90,000원
선택한 가격·정가 전환 안내

CS 연락처
[010-1234-5678                    ]
오류·재시도 안내
[주문하기                  ][취소]
다음 화면의 결제 안내
```

금액 블록 하나에만 옅은 바탕을 사용하고 추가 장식·그라데이션·카드 중첩은 만들지 않는다. 기능상 필요한 조회 상태와 가격 적용 근거가 시각적 위계를 결정한다.

## 검증

기존 가격 제안 Playwright에 지연 응답·503→성공·입력 중 오류·새 제안 도착 회귀를 추가한다. SSR은 읽기 전용 fixture로 고정하고 주문 POST는 브라우저에서 가로채 주문 금액·제안 ID를 확인한다. 기존 만료·거부·다중 제안 선택 테스트와 320/375/768px Orca 화면도 확인한다. 운영 결제창과 실제 PG는 실행하지 않는다.
