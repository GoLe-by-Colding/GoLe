# 구매 금액 확인 요구사항

- R1. 로그인한 구매자의 가격 제안 조회가 끝나기 전에는 정가 주문을 시작하지 않는다. 조회 실패를 제안 없음으로 취급하지 않는다.
- R2. 조회 중·실패·재시도를 구분하고, 재시도 후 수락 제안이 있으면 해당 제안가로 구매를 이어 간다.
- R3. 연락처 입력 중에도 조회가 실패하면 주문을 잠시 막고 입력값을 보존한다. 다시 확인한 뒤 주문할 수 있다.
- R4. 정가 확인 뒤 새 수락 제안이 도착하면 변경된 금액을 보여 주고 한 번 더 확인받는다. 이미 선택한 유효 제안은 다른 제안이 도착해도 유지한다.
- R5. 주문 화면 전환 전에 실제 주문 금액과 적용된 제안 여부를 명확히 보여 준다. 제안 만료·서버 거부 후 정가 전환도 기존처럼 명시적으로 확인받는다.
- R6. 공통 Button·Field·Input 및 기존 브랜드 토큰을 사용한다. 모바일에서 긴 금액·안내·오류가 가로로 넘치지 않는다.
- R7. 기존 결제·공개 잠금을 보존한다. 사용자 프리뷰 3000/API8090에 쓰지 않고, 격리 fixture와 기존 Playwright로 회귀를 검증한다.
- R8. 기능 브랜치의 `feature/` 접두사를 PR 규약에서도 허용한다. 기존 `feat/` 등 브랜치, 커밋·PR 제목의 conventional type, 작업 브랜치→dev→main 경계는 유지하며 계정 접두사는 허용하지 않는다.
