# 홍보 피드백 메모리 요구사항

1. 관리자가 반려하면 당시 캡션, 최종/원본 이미지 경로, 화면 설명표, 출처, 반려 원문, 검토자/시각을 `promotion_feedback`에 별도로 보존한다. 게시물 재제출이나 평가 수정이 이 기록을 덮어쓰지 않는다. 반려와 기록은 함께 성공하거나 함께 실패한다.
2. 경험 기억은 반려 사례, 지식/절차 기억은 사람이 확정한 지침으로 구분한다. 작업 기억은 실행마다 구성한다. 기존 MongoDB와 UUID 문자열 ID를 사용하며 새 의존성/벡터 검색은 추가하지 않는다.
3. 다음 홍보 실행은 생성 여부 사전 검사 전에 미처리 반려 최대 3건에서 지침 최대 3개를 제안한다. 제안 없음도 처리 완료로 남긴다. 모델 제안은 자동 활성화하지 않는다. 반려/출처 텍스트는 신뢰할 수 없는 데이터로 취급한다.
4. 관리자는 제안의 내용/적용 범위를 수정하고 확정하거나 기각한다. 활성 지침은 해제할 수 있다. 원 제안자는 자기 지침을 확정할 수 없고, 다른 사람이 내용을 수정한 뒤 확정하는 것은 허용한다.
5. Claude는 CAPTION/SCREEN_SELECTION, Codex는 IMAGE_EDIT에 해당하는 관련 사례/활성 지침을 받는다. 종류와 화면 경로를 이용해 관련 사례 최대 3건, 활성 지침 최대 8개를 선택한다. 미확정/기각/해제 지침은 생성에 적용하지 않는다.
6. 실행 원장에 사용한 피드백 ID와 활성 지침의 당시 내용을 보존한다. 성찰 모델/검증/저장 실패는 별도 오류로 알리고 조회한 기존 작업 기억으로 생성을 계속한다. 작업 기억 조회 실패는 최신 지침을 확인할 수 없으므로 생성을 중단한다. 실제 모델 품질과 로컬 자동 검증을 구분한다.
7. 기존 반려/재제출/실행 기록 API와 과거 MongoDB 문서는 호환한다. 이미지의 편집 지시문 제한은 6,000자로 통일한다. 현재 게시물/이미지는 불변이므로 기존 PROMOTION_POST 연결을 보존하며 같은 미디어를 다른 target으로 재연결하지 않는다.

8. 지침 수정과 확정은 검토한 `expectedVersion`을 요구한다. 다른 관리자의 변경이 끼면 HTTP 409로 차단하고 화면은 최신 내용을 다시 보여준다. 같은 버전의 동시 변경은 한 건만 성공하고 기존 버전 없는 문서는 0으로 읽는다.
