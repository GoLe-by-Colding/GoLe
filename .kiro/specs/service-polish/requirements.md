# GoLe 제품 완성도 개선 — 2026-10-09

## 사용자 목표

실서비스 수준으로 기획·디자인·앱 동선을 개선하고 GoLe-obsidian도 현재 구현에 맞춘다.
현재 고래가 무섭다는 피드백을 반영해 귀여운 캐릭터로 수정한다. 기존 Orca Claude가 구현하고
Codex가 실행 화면·통합을 검수한다. API·웹·Metro는 사용자가 볼 수 있는 Orca 포그라운드 터미널에 둔다.

## 제품 기준

GoLe는 **브릭의 상태와 가격 근거를 보고, 수집과 거래를 이어 가는 마켓플레이스**다.
고래는 친근한 안내자이고 상품 사진·가격·상태보다 앞서지 않는다. Pawpong에서 참고할 것은
완료 가능한 동선·명확한 상태·일관된 화면이라는 품질 기준이다. 다른 제품의 메뉴나 사업 모델은 복제하지 않는다.

1. 고래는 원래의 **옆모습 브릭 고래**(9f581c70 = 17b1010e^)를 친근하게 다듬어 되살리고 웹과 앱의 생성 자산을 동기화한다.
   같은 날 그린 정면 고래(스터드 머리·아기 고래)는 사용자 교정("왜 앞면으로 된거야? 원래 레고블럭처럼 옆면이였잖아")으로 폐기했다.
2. 홈은 흰색 기반의 여백과 코발트 주 버튼, 절제된 골드로 정리한다. 모바일 첫 화면에서
   서비스 목적과 주 행동을 읽을 수 있어야 한다. 실제 존재하지 않는 거래량·후기·안전보장은 만들지 않는다.
3. 검색은 이미지·가격·상태가 먼저 읽히게 한다. 작은 화면에서도 상품 비교와 검색·필터가 가능해야 한다.
   360px 이상 휴대폰은 2열로 나란히 비교하고, 320px급은 긴 금액이 넘치지 않게 1열을 유지한다. 상태 등급·구성·
   부품 누락·예약중 같은 고지는 폭이 좁아도 숨기지 않는다. 빈 사진은 기존 브릭 패턴을 유지하고 실제 판매자 사진을 대체하지 않는다.
   휴대폰의 입력·선택란은 글자를 16px 이상으로 둬 iOS가 초점 때 화면을 확대하지 않게 한다(viewport 확대 금지는 쓰지 않는다).
4. 상세는 판매 가격과 시세 근거를 구분하되, 판매가 바로 아래에 같은 등급 추정 시세와의 차이를 보여 구매자가 가격을
   그 자리에서 판단하게 한다. 목록 카드에도 같은 규칙의 한 줄을 둔다. 근거가 약하면(감가 모델·참고 단계) 비교하지 않는다.
   상세는 판매 가격과 시세 근거를 구분한다. 전체 등급 체결가를 해당 매물 등급의 가격처럼 보이게 하지 않고,
   추정가를 즉시 실행 가능한 거래 가격처럼 부르지 않는다.
   판매 등록·수정 화면도 세트 한 벌로 팔 때 가격 칸 아래에 같은 상태 추정 시세와 넣은 가격의 차이를 보인다. 가격을 대신
   채우지 않고, 근거가 약하면 비교 대신 그 이유(체결 전·표본 부족)를 짧게 말한다. 미니피규어·부품은 세트 시세와 견주지 않는다.
5. RN은 탭·안전 영역·기기 알림·네이티브 뒤로 가기를 맡고 본문은 웹을 재사용한다.
   서버 알림의 쿼리·해시를 보존해 채팅방·주문·커뮤니티·부품 요청으로 이동한다. 외부 URL은 내부 경로로 취급하지 않는다.
   웹 안의 링크·이동이 다른 탭의 화면(`/`·`/search`·`/sell`·`/chat`·`/profile`)을 가리키면 선택된 RN 탭과 실제 웹 목적지가
   어긋나지 않게 그 탭으로 넘긴다. 경로·query·hash를 보존하고 작성 중인 폼을 무조건 새로 고치지 않는다. 웹→앱 요청은
   정확한 신뢰 원점과 고정된 이동 메시지·경로 검증만 쓰며, 임의 스크립트·토큰 명령이나 쿠키 복사를 하지 않는다.
   앱이 실제로 쓰는 카메라·사진 권한에는 용도 문구를 둔다.
6. 로딩·비어 있음·오류·로그인 필요·기능 준비 중을 구분하고 각각 가능한 다음 행동을 제공한다.
   기존 판매자 확인·결제·정산 게이트와 팀원 기능을 유지한다.
7. 문서는 현재 코드, 로컬 실화면, 실기기/운영 미검증, 제품 제안을 구분한다.
   실물 결제와 판매자 수동 정산의 계약·검증 조건을 명시하고 기존의 “추가 계약 없음” 같은 단정을 정정한다.
