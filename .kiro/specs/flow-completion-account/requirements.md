# 계정·컬렉션·알림 흐름 완성 요구사항

## 확인한 끊김

- 내 정보의 닉네임 설정 링크가 `/onboarding`만 열어 완료 후 홈으로 이동한다.
- 알림 읽음 성공이 헤더 벨에 전달되지 않아 기존 개수가 다음 30초 폴링까지 남는다.
- 알림 읽음 실패가 목록 조회 실패와 같은 상태를 써 이미 조회한 목록 전체를 감춘다.
- 알림 설정을 연속 변경하면 병렬 PUT의 늦은 응답이 앞서 완료한 변경을 덮어쓸 수 있다.
- WebView의 푸시 등록은 첫 수화의 비로그인 스냅샷을 로그아웃으로 처리하며, 등록 중
  로그아웃하거나 토큰이 교체될 때 요청 순서와 기존 토큰 해제를 보장하지 않는다.

## 수락 조건

- A1. 내 정보에서 시작한 프로필 완성은 끝난 뒤 내 정보로 돌아온다. 기존 로그인·가입·
  이메일 인증·비밀번호 재설정의 안전한 복귀 경로를 보존한다.
- A2. 알림 한 건/전체 읽음이 성공하면 같은 계정의 헤더 개수를 즉시 다시 조회한다.
  읽음 실패는 목록을 유지하고 사용자가 다시 시도할 수 있게 알린다.
- A3. 알림 설정의 여러 분류를 연달아 눌러도 모두 저장되고 새로고침 후 유지된다.
  실패한 분류만 되돌리며 거래 필수 알림은 계속 잠근다.
- A4. WebView 세션 복원은 푸시 해제를 발생시키지 않는다. 등록 도중 로그아웃과 토큰
  교체는 순서대로 정리하고 실패한 등록/해제는 포커스 복귀에서 다시 시도한다.
  해제 응답 유실 후 재로그인과 다른 WebView 등록 뒤 늦게 끝난 해제에서도 현재 계정의
  등록을 복구한다. 해제 전에 시작한 POST의 늦은 응답을 유효한 완료 캐시로 인정하지 않는다.
- A5. 온보딩 조회 일시 실패는 같은 화면에서 재시도할 수 있다. 외부 OAuth/SMS/FCM
  발송이나 운영 공개·결제 설정은 변경하지 않는다.
- A6. Android는 알림 권한을 요청하기 전에 알림 채널을 만든다. 실제 알림 발송 없이
  네이티브 API 호출 순서와 권한 거절·기기 미지원 분기를 검증한다.
- A7. 관리자 정지 해제는 이메일 인증을 대신하지 않는다. 미인증 계정의 정지·해제 후에도
  이메일 인증이 필요하며, 정지 중 인증 코드로 정지를 해제할 수 없다. 기존 탈퇴 잠금은 보존한다.

## 검증 경계

- 브라우저 수동 검증은 전용 Orca 탭과 루트가 준비한 E2E 3002/API 8080에서 한다.
- 사용자 3000/API 8090 로그인 상태는 변경하지 않는다.
- 합성 API 응답 회귀 테스트와 실제 E2E API 검증을 구분한다. 실기기·실 OAuth·SMS·FCM은
  실행하지 않은 경우 명시적으로 미검증으로 남긴다.
